# Папка `app/Auth` — совместимость со старыми паролями

Проект перенесён с Python/Flask (Werkzeug) на Laravel. При импорте базы данных
пароли пользователей были перенесены **как есть** — в формате хешей Werkzeug
(`scrypt:...` и `pbkdf2:sha256:...`), а не Laravel-bcrypt.

Без этой папки старые пользователи после миграции не смогли бы войти в свои
аккаунты (Laravel умеет проверять только bcrypt/argon). Классы из `app/Auth`
решают эту проблему: **старый пароль продолжает работать, а при первом входе
хеш автоматически заменяется на современный bcrypt** — пользователь ничего не
замечает и не обязан сбрасывать пароль.

## LegacyPasswordVerifier — проверка старых хешей

Статический + экземплярный класс-«верификатор» Werkzeug-хешей.

### `isLegacy(string $hash): bool`
Определяет, является ли хеш «старым»: начинается с `scrypt:` или `pbkdf2:`.

### `verify(string $password, string $hash): bool`
Проверяет пароль по старому хешу. Формат Werkzeug-хеша:
`метод$соль$ожидание` (3 части через `$`).

Поддерживаются два алгоритма:

| Алгоритм | Как проверяется |
|---|---|
| `pbkdf2:sha256` | нативной функцией PHP `hash_pbkdf2()` |
| `scrypt` | вызовом OpenSSL (`EVP_PBE_scrypt`) через **FFI** — без внешних процессов, пароль не покидает PHP |

Важно для безопасности (защита от подделки хеша):
- параметры алгоритма валидируются до вычисления: число раундов PBKDF2
  ограничено (1…2 000 000), параметры scrypt (`N`, `r`, `p`) — в разумных
  диапазонах, `N` обязан быть степенью двойки;
- сравнение хешей — через `hash_equals()` (constant-time, защита от
  timing-атак).

## LegacyUserProvider — провайдер аутентификации

Наследует стандартный `EloquentUserProvider` Laravel и переопределяет два
метода:

### `validateCredentials($user, $credentials): bool`
- Если хеш пользователя **старый** (Werkzeug) → проверяет пароль через
  `LegacyPasswordVerifier`.
- Иначе → стандартная проверка Laravel (bcrypt/argon).

### `rehashPasswordIfRequired($user, $credentials, $force = false): void`
- Если хеш **старый** → сразу пересоздаёт его в bcrypt средствами Laravel
  (`$this->hasher->make(...)`) и сохраняет.
- Иначе → стандартное поведение Laravel (например, апгрейд алгоритма).

## Как это работает (для презентации)

```
Пользователь из старой БД (хеш scrypt/pbkdf2)
   │ вводит свой старый пароль
   ▼
LegacyUserProvider::validateCredentials
   ├── хеш «старый»?  → LegacyPasswordVerifier::verify (FFI/OpenSSL или hash_pbkdf2)
   └── хеш «новый»?   → стандартный bcrypt Laravel
   │ пароль совпал
   ▼
rehashPasswordIfRequired → хеш заменяется на bcrypt
   │
   ▼
Дальше пользователь входит как обычный (bcrypt), миграция завершена
```

**Результат:** плавная миграция без потери доступа — каждый старый аккаунт
«переезжает» на современные хеши при первом же входе, исходная база при этом
не изменяется (импорт читает её только для чтения).
