# Консольные команды (app/Console/Commands)

Команды Laravel Artisan — служебные скрипты, которые запускаются из терминала
(`php artisan ...`) и не имеют отношения к HTTP-запросам. В проекте их три:
подготовка локального окружения, импорт старой Flask-базы и выдача прав модератора.

## 1. BootstrapLocal — `app:bootstrap`

**Назначение:** «одна кнопка» для запуска проекта с нуля (локально/в Docker).

Что делает по шагам:
1. Запускает `db:seed` с `DictionarySeeder` — наполняет справочники
   (типы медиа, статусы, жанры, роли).
2. Если в конфигурации указан файл старой Flask-базы (`legacy.source`) и он
   существует → автоматически вызывает команду `legacy:import`.
3. В локальной среде (`local`) создаёт администратора `admin` (пароль берётся
   из `.env`, `legacy.admin_password`), если такого пользователя ещё нет.

**Результат:** пустой проект превращается в готовый к работе: справочники
наполнены, данные импортированы, есть админ.

## 2. ImportLegacy — `legacy:import {source}`

**Назначение:** импорт данных из старой базы Flask (SQLite) в новую Laravel-базу.
Главная «миграционная» команда проекта.

### Безопасность и защита от ошибок
- Источник открывается **только для чтения** (`PDO::SQLITE_OPEN_READONLY`) —
  исходная база не изменяется никогда.
- Проверка, что источник и назначение — разные базы.
- **Идемпотентность:** SHA-256 хеш файла источника сохраняется в таблице
  `legacy_imports`; повторный запуск с той же базой ничего не меняет.
- После импорта хеш источника проверяется ещё раз — если файл менялся во
  время работы, импорт считается ошибкой.
- Перед стартом проверяется, что в источнике есть все ожидаемые таблицы
  (`user`, `user_media`, `collection`, `collection_item`, `episode_note`,
  `tv_season_progress`, `post`).

### Что импортируется (в одной транзакции)

| Таблица Flask | Куда | Примечание |
|---|---|---|
| `user` | `users` | пароль-хеш Werkzeug переносится как есть (работает `app/Auth`) |
| `user_media` | `entries` | записи дневника, статусы мапятся по кодам |
| `collection` | `user_lists` | публичным спискам генерируется новый `share_token` |
| `collection_item` | `list_media` | содержимое списков |
| `tv_season_progress` | `season_progress` | прогресс по сезонам сериалов |
| `episode_note` | `episode_notes` | заметки к сериям |
| `post` | `legacy_posts` | архив (в старом приложении не использовалась) |

Особая логика:
- **Медиа по TMDB:** для всех `(tmdb_type, tmdb_id)` из источников создаются
  записи `Media` со статусом `external` и временным названием
  («Фильм TMDB #123»); метаданные подтянутся из TMDB при первом открытии.
- **Аватары/обложки:** пути `/static/uploads/...` переключаются на локальный
  storage (`legacy/<имя файла>`).
- Дубликаты исключаются через `insertOrIgnore` и проверку по `legacy_id`.

**Результат:** таблица с количеством перенесённых записей по каждому типу данных.

## 3. MakeModerator — `user:moderator {login} {--admin}`

**Назначение:** выдать права модерации существующему аккаунту.

- Аргумент: `login` пользователя.
- Опция `--admin`: назначить роль `admin` вместо `moderator`.
- Если аккаунт не найден → ошибка и выход с кодом `FAILURE`.
- Иначе меняет поле `role` в `users` и сохраняет.

**Зачем:** в продакшене админ не создаётся автоматически (см. `BootstrapLocal`),
права модератора/админа выдаются вручную командой — это проще и безопаснее,
чем править БД руками.

## Как это работает вместе (для презентации)

```
Новый сервер / Docker:
   php artisan app:bootstrap
      ├── db:seed (справочники)
      ├── legacy:import (если есть старая БД)
      └── создание admin (только local)

Позже, вручную:
   php artisan user:moderator ivan          → роль moderator
   php artisan user:moderator ivan --admin → роль admin
```
