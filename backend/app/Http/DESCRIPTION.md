# Папки `Http/Resources` и `Http/Middleware`

## 1. Resources — формат ответа API

**Resource** (ресурс) — это «шаблон ответа»: он определяет, **какие поля**
модели попадут в JSON, который увидит клиент. Модель можно отдать напрямую,
но тогда в ответ уйдут все столбцы таблицы (включая `password`, `poster_key`
и служебные поля). Resource — это «вид» модели для API: безопасный,
предсказуемый и компактный.

### UserResource — представление пользователя
Единственный ресурс проекта. Используется в `AuthController` (`register`,
`login`, `me`) и `ProfileController` (`update`) — везде, где API отдаёт
данные о текущем пользователе.

| Поле в JSON | Источник |
|---|---|
| `id` | `users.id` |
| `name` | имя |
| `login` | логин |
| `email` | email |
| `role` | роль (`user` / `moderator` / `admin`) |
| `language` | язык интерфейса |
| `theme` | тема оформления |
| `avatar_url` | готовый URL аватара (из `avatar_key`: внешний http или `/storage/...`; `null`, если аватара нет) |
| `created_at` | дата регистрации |

**Что намеренно исключено:** `password` (хэш), `remember_token`, служебные
поля — они никогда не попадают в JSON.

**Зачем это нужно (для презентации):**
- API отдаёт только то, что нужно клиенту — меньше трафика, меньше утечек.
- Формат ответа зафиксирован в одном месте: если модель изменится,
  контроллеры не сломаются.
- `avatar_url` — вычисляемое поле: клиент получает готовую ссылку на картинку,
  а не «сырой» ключ файла.

## 2. Middleware — контроль доступа

**Middleware** (посредник) — код, который выполняется **до** контроллера:
проверяет, имеет ли право запрос вообще дойти до обработчика. В проекте
один middleware, он закрывает админские функции.

### EnsureIsModerator — «только модераторы и админы»
- **Где применяется:** к маршрутам модерации (`ModerationController::approve`,
  `reject` и прочим) — через роутер Laravel.
- **Логика:**
  1. Берёт текущего пользователя из запроса.
  2. Если пользователя нет (не авторизован) или его роль **не** `moderator`
     и не `admin` → сразу JSON **403**: «Доступ запрещен. Требуются права
     модератора или администратора.»
  3. Иначе — пропуск запроса дальше (`$next($request)`).

**Зачем это нужно (для презентации):**
- Защита на уровне маршрута: даже если клиент сам вызовет эндпоинт одобрения
  заявки, без нужной роли он получит 403 и ни одна заявка не будет обработана.
- Работает в связке с моделями: `User::isModerator()` / `isAdmin()` дают ту же
  проверку в коде, а middleware — на уровне HTTP.

## Как это работает вместе (кратко)

```
Запрос клиента
   │
   ▼
Middleware (EnsureIsModerator и др.) ── нет прав? ──► JSON 403
   │ да
   ▼
Контроллер (Api/V1/...)
   │
   ▼
Модель (Eloquent)
   │
   ▼
Resource (UserResource) ──► JSON-ответ клиенту
```

Middleware решает, **можно ли** выполнить действие; Resource решает,
**что показать** в ответе. Оба слоя — часть «обёртки» API поверх моделей.
