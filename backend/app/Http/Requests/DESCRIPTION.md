# Описание FormRequest-классов (app/Http/Requests)

FormRequest — это «входные ворота» API: каждый класс описывает, **какие поля**
принимает эндпоинт и **как их валидировать**. Laravel автоматически проверяет
входящий запрос до того, как он попадёт в контроллер: при ошибке сразу
возвращается JSON с 422 и списком ошибок — контроллеры остаются чистыми,
логика валидации отделена от логики обработки.

Структура папки:

```
Requests/
├── Auth/
│   ├── LoginRequest.php
│   └── RegisterRequest.php
├── AddMediaToListRequest.php
├── StoreEntryRequest.php
├── StoreMediaRequest.php
├── StoreUserListRequest.php
└── UpdateMediaRequest.php
```

## Папка Auth — аутентификация

### LoginRequest — вход в систему
Валидирует данные для `AuthController::login`.
| Поле | Правила |
|---|---|
| `login` | обязательно, строка (логин **или** email — определяется в контроллере) |
| `password` | обязательно, строка |
| `remember` | опционально, boolean («запомнить меня») |

### RegisterRequest — регистрация
Валидирует данные для `AuthController::register`.
| Поле | Правила |
|---|---|
| `name` | обязательно, до 100 символов |
| `login` | обязательно, 3–50 символов, только буквы/цифры/`_`/`-`, **уникален** в таблице `users` |
| `email` | обязательно, корректный email, **уникален** |
| `password` | обязательно, минимум 8 символов, `confirmed` (требует `password_confirmation`) |
| `language` | опционально: `ru` / `en` |
| `theme` | опционально: `light` / `dark` / `system` |

## Записи дневника и списки

### StoreEntryRequest — запись в кинодневник
Валидирует создание/обновление записи (`Entry`) с детализацией по сериям.
| Поле | Правила |
|---|---|
| `media_id` | обязательно, должен существовать в `media` |
| `status_id` | обязательно, должен существовать в `statuses` |
| `date` | опционально, дата |
| `rating` | опционально, целое 1–10 (с русскими сообщениями об ошибке) |
| `note` | опционально, строка до 5000 символов |
| `episodes` | опциональный массив отметок серий |
| `episodes.*.episode_id` | обязательно, существует в `episodes` |
| `episodes.*.watched` | обязательно, boolean |
| `episodes.*.rating` | опционально, 1–10 |
| `episodes.*.note` | опционально, строка до 1000 символов |

Особые сообщения (`messages()`): «Оценка должна быть от 1 до 10.» — пользователь
видит понятный текст вместо технического правила.

### StoreUserListRequest — создание списка
| Поле | Правила |
|---|---|
| `name` | обязательно, до 255 символов |
| `is_public` | опционально, boolean (публичный список с ссылкой) |

### AddMediaToListRequest — добавление медиа в список
| Поле | Правила |
|---|---|
| `media_id` | обязательно, должен существовать в `media` |

## Медиа (каталог)

### StoreMediaRequest — создание записи каталога
Полный набор полей для добавления фильма/сериала.
| Поле | Правила |
|---|---|
| `title_ru` | обязательно, до 255 символов |
| `title_en` | опционально, до 255 |
| `original_title` | опционально, до 255 |
| `description_ru` | опциональная строка (описание) |
| `type_id` | обязательно, существует в `media_types` |
| `franchise_id` | опционально, существует в `franchises` |
| `release_date` | опционально, дата |
| `genre_ids` | **обязательный массив, минимум 1** (с сообщением «Необходимо выбрать хотя бы один жанр.») |
| `genre_ids.*` | каждый id существует в `genres` |
| `companies` | опциональный массив компаний |
| `persons` | опциональный массив персон (актёры/режиссёры) |

### UpdateMediaRequest — обновление записи каталога
«Мягкая» версия Store: почти все поля `sometimes`/`nullable` — можно прислать
только то, что изменилось (частичное обновление).
| Поле | Правила |
|---|---|
| `title_ru` | опционально, до 255 |
| `title_en`, `original_title` | опционально, до 255 |
| `description_ru` | опциональная строка |
| `type_id` | опционально, существует в `media_types` |
| `franchise_id` | опционально, существует в `franchises` |
| `release_date` | опционально, дата |
| `genre_ids` | опциональный массив, каждый id существует в `genres` |

## Как это работает (для презентации)

1. **FormRequest** — класс-«контракт» эндпоинта: список полей + правила.
2. **authorize()** — проверка прав (в проекте все `true`, т.к. доступность
   маршрутов уже ограничена middleware аутентификации).
3. **rules()** — правила валидации Laravel: обязательность, типы, диапазоны,
   существование в БД (`exists:`), уникальность (`unique:`).
4. **messages()** — русские сообщения об ошибках для пользователя.
5. При нарушении правил запрос **не доходит до контроллера** — клиент сразу
   получает JSON 422 с перечнем ошибок по полям (удобно для показа в форме).
