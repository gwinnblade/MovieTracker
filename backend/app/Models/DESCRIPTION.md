# Описание моделей данных (app/Models)

Проект — **кинодневник** в духе Кинопоиска: пользователи ведут учёт того, что они
смотрели, смотрят сейчас или планируют посмотреть, ставят оценки, ведут прогресс
сериалов по сезонам и эпизодам, собирают собственные списки фильмов. Каталог
медиа (фильмы/сериалы) пополняется пользователями через систему модерации, а
данные о релизах синхронизируются с API **TMDB**.

## Схема связей (ER-диаграмма)

```mermaid
erDiagram
    USER ||--o{ ENTRY : "ведёт дневник"
    USER ||--o{ USER_LIST : "создаёт списки"
    USER ||--o{ MODERATION_REQUEST : "отправляет заявки"
    USER ||--o{ MODERATION_REQUEST : "модерирует"
    MEDIA ||--o{ ENTRY : "оценивается"
    MEDIA ||--o{ EPISODE : "состоит из серий"
    MEDIA }o--|| TYPE : "тип (фильм/сериал)"
    MEDIA }o--o| FRANCHISE : "франшиза"
    MEDIA }o{|| GENRE : "жанры"
    MEDIA }o{|| PERSON : "актёры/режиссёры"
    MEDIA }o{|| COMPANY : "студии"
    PERSON }o--|| ROLE : "роль в производстве"
    EPISODE ||--o{ EPISODE_ENTRY : "отмечается просмотренным"
    ENTRY ||--o{ EPISODE_ENTRY : "детализация по сериям"
```

## Пользовательские модели

### User — пользователь
Основная модель аутентификации (наследует `Authenticatable`).
- **Поля:** `name`, `login`, `email`, `password` (хэшируется), `role` (`user` / `moderator` / `admin`), `language`, `theme`, `avatar_key`.
- **Связи:** `entries()` — записи дневника, `lists()` — собственные списки, `moderationRequests()` — отправленные заявки, `moderatedRequests()` — заявки, которые пользователь обработал как модератор.
- **Методы:** `isAdmin()`, `isModerator()` — проверка ролей (админ считается и модератором).

### Entry — запись в кинодневнике
Центральная модель проекта: «пользователь X относится к фильму Y так-то».
- **Поля:** `user_id`, `media_id`, `status_id` (статус: посмотрено / в планах и т.д.), `date`, `rating` (оценка), `note` (личное впечатление), `progress`, `seasons_watched`, `episodes_watched` — агрегированный прогресс для сериалов.
- **Связи:** `user()`, `media()`, `status()`, `episodeEntries()` — детализация просмотра по отдельным сериям.

### UserList — пользовательский список
Личные подборки пользователя («избранное», «посмотреть с семьёй» и т.п.).
- **Поля:** `user_id`, `name`, `description`, `cover_key` (обложка), `is_public`, `share_token` — токен для публичного шаринга списка.
- **Связи:** `user()`, `media()` — многие-ко-многим через pivot-таблицу `list_media` с датой добавления (`added_at`).

### EpisodeEntry — отметка просмотра серии
Детализация записи дневника для сериалов: какие именно серии просмотрены.
- **Поля:** `entry_id`, `episode_id`, `watched` (boolean), `rating` (оценка серии), `note`.
- **Связи:** `entry()`, `episode()`.

### SeasonProgress — прогресс по сезонам сериала
Хранит, сколько серий просмотрено в каждом сезоне и статус сезона.
- **Поля:** `user_id`, `media_id`, `season`, `watched` (число просмотренных серий), `status` (например, `completed`).
- Используется для статистики профиля (суммарное число просмотренных эпизодов) и обновления счётчиков `Entry`.

### EpisodeNote — заметка к серии
Личная заметка пользователя к конкретной серии (сезон/эпизод).
- **Поля:** `user_id`, `media_id`, `season`, `episode`, `note`.

## Каталог медиа

### Media — фильм или сериал
Главная сущность каталога.
- **Поля:** `type_id` (тип), `franchise_id`, `title_ru`, `title_en`, `original_title`, `description_ru`, `poster_key`, `release_date`, `moderation_status`.
- **TMDB-синхронизация:** `tmdb_type`, `tmdb_id`, `tmdb_data` (JSON с данными из TMDB), `tmdb_synced_at`, `tmdb_failed_at` — позволяет отслеживать, когда и с каким результатом была синхронизация.
- **Атрибут `poster_url`:** автоматически формирует URL постера (внешний http, путь к TMDB-изображению или локальный storage).
- **Связи:** `type()`, `franchise()`, `genres()` (многие-ко-многим), `persons()` (с pivot: роль и имя персонажа), `companies()` (с pivot: роль компании), `episodes()` (отсортированы по сезону и номеру), `entries()`.

### Episode — серия сериала
- **Поля:** `media_id`, `season`, `number`, `title`.
- **Связи:** `media()`, `episodeEntries()`.

### Type — тип медиа (таблица `media_types`)
Справочник типов: фильм, сериал и т.д.
- **Поля:** `code`, `name_ru`, `name_en`. Без таймстемпов (справочные данные).
- Используется в `Media::type()` и `ModerationRequest::type()`.

### MediaType — устаревшая модель типа медиа
Аналог `Type` (таблица `media_types`). Осталась для совместимости:
`ReferenceController` отдаёт её в API справочника. Новых связей не добавлять —
использовать `Type`.

### Franchise — франшиза
Иерархический справочник франшиз (само-ссылка «родитель/дети», например
«Marvel» → «Мстители»).
- **Поля:** `name`, `parent_id`.
- **Связи:** `parent()`, `children()`, `media()`.

### Genre — жанр
Справочник жанров (двуязычный: `name_ru`, `name_en`). Связан с `Media` многие-ко-многим.

### Person — персона (актёр, режиссёр и т.д.)
- **Поля:** `name`, `photo_key`, `tmdb_id` (связь с данными TMDB).
- **Связи:** `media()` — pivot `person_media` хранит `role_id` (какую роль сыграл) и `character` (имя персонажа); `roles()`.

### Role — роль в производстве
Справочник ролей: актёр, режиссёр, сценарист и т.д.
- **Поля:** `code`, `name_ru`, `name_en`.

### Company — студия/компания производства
- **Поля:** `name`.
- **Связи:** `media()` — pivot `company_media` с `role_id` (какую роль компания сыграла: продюсер, дистрибьютор и т.д.).

## Модерация

### ModerationRequest — заявка на добавление/изменение медиа
Пользователи предлагают контент для каталога; модераторы принимают или отклоняют.
- **Поля:** `user_id` (автор), `title_ru`, `title_en`, `type_id`, `release_year`, `description_ru`, `status` (`pending` / `approved` / `rejected`), `rejection_reason`, `poster_key`, `tmdb_data`, `tmdb_id`, `tmdb_type`, `action`, `genres_provided`.
- **Результат модерации:** `media_id` (созданное медиа), `moderator_id`, `resolved_at`.
- **Связи:** `user()`/`author()`, `type()`, `genres()` (через pivot `genre_moderation_request`), `media()`, `moderator()`.

## Справочные модели (статусы)

### Status — статус записи дневника
Справочник статусов отношений пользователя с медиа: например «посмотрено»,
«смотрю сейчас», «в планах».
- **Поля:** `code`, `name_ru`, `name_en`.
- **Связи:** `entries()`.

## Ключевые сценарии работы моделей

1. **Дневник:** пользователь создаёт `Entry` (медиа + статус + оценка/заметка). Для сериалов дополнительно заполняются `EpisodeEntry`, `SeasonProgress`, `EpisodeNote` — счётчики `seasons_watched` / `episodes_watched` в `Entry` обновляются автоматически.
2. **Каталог:** медиа из каталога (`Media`) связываются со справочниками `Type`, `Franchise`, `Genre`, `Person` (+`Role`), `Company`; данные обогашаются из TMDB.
3. **Модерация:** пользователь отправляет `ModerationRequest` → модератор принимает (создаётся `Media`) или отклоняет с причиной.
4. **Списки:** пользователь собирает `UserList` из медиа каталога, может сделать его публичным через `share_token`.
