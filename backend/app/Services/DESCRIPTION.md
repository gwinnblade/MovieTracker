# Сервисы (app/Services)

Сервисный слой — «мозг» интеграции с внешним миром. В проекте два сервиса,
которые работают в паре: `TmdbService` общается с внешним API TMDB, а
`MediaLibrary` превращает эти данные в записи каталога Laravel.

## TmdbService — клиент API TMDB

Единая точка доступа к `api.themoviedb.org`. Все запросы идут через один
приватный метод `request()`, который добавляет:

- **Кэш** (`Cache::remember`): ответ кэшируется по SHA-256 от URL+параметров.
  Список/поиск — 30 минут, детали и сезоны — 24 часа. TMDB не нагружается
  лишний раз, ответы быстрее.
- **Язык** `ru-RU` по умолчанию (русские описания и названия).
- **Таймауты**: соединение 5 с, общий 18 с — запрос не «висит» бесконечно.
- **Ошибки** превращаются в HTTP-исключения с русскими сообщениями:
  - нет `TMDB_API_KEY` → 503 «Добавьте TMDB_API_KEY в backend/.env...»
  - нет соединения → 503 «Проверьте VPN и настройки DNS»
  - 404 → «Этот фильм или сериал не найден в TMDB»
  - 401/403 → «TMDB отклонил токен...»
  - прочее → 503 «TMDB временно недоступен»

### Публичные методы

| Метод | Что делает |
|---|---|
| `search($query, $type, $page)` | поиск по TMDB (multi / movie / tv) |
| `trending($type, $page)` | тренды недели |
| `details($type, $id)` | детали релиза + актёрский состав, режиссёры, жанры, компании, сезоны |
| `season($id, $season)` | список серий конкретного сезона сериала |

Внутренние помощники:
- `title()` — нормализует «сырой» ответ TMDB в единый формат (названия на
  ru/en, постеры, рейтинг, тип).
- `page()` — оборачивает список в пагинацию (`data`, `current_page`,
  `last_page`, `total`, `per_page`).

## MediaLibrary — «библиотека» каталога

Превращает данные TMDB в модели Laravel (`Media`, `Person`, `Company`, `Genre`,
`Role`) и обратно. Используется в `ModerationController`, `TmdbController`,
`MediaController`.

### Публичные методы

| Метод | Что делает |
|---|---|
| `external($type, $id)` | находит или создаёт `Media` по `(tmdb_type, tmdb_id)` со статусом `external`; если уже есть — обновляет |
| `refresh(Media $media)` | «подтянуть свежие данные»: если с последней синхронизации прошло > 1 дня (или последняя попытка была > 1 часа назад) — запрашивает TMDB и применяет; при ошибке помечает `tmdb_failed_at` |
| `apply(Media $media, array $data, bool $publish = false)` | применяет данные к записи: всегда обновляет `tmdb_data`, `tmdb_synced_at`; если медиа **не** `approved` (или `$publish`) — также обновляет названия, описание, постер, жанры; при `$publish` — также актёров/режиссёров/компании |
| `credits(Media $media, array $data)` | синхронизирует персоны (режиссёры + актёры) и компании: создаёт `Person`/`Company` по `tmdb_id`/имени, привязывает через pivot-таблицы с `role_id` и `character` |
| `serialize(Media $media)` | собирает «полный» JSON медиа для ответа: модель + `persons` (с ролями) + поля из `tmdb_data` (cast, directors, seasons, runtime, vote_average и т.д.) |

### Ключевые правила

- **Не перетирает одобренное:** если `moderation_status === 'approved'`,
  `apply()` не меняет названия/описание/жанры — только `tmdb_data` и метки
  синхронизации. Это защищает ручные правки модератора от «перезаписи» TMDB.
- **Публикация** (`$publish = true`) — принудительное применение всех полей,
  включая персоны и компании (используется при одобрении заявки).
- **Персоны** создаются по `tmdb_id` (если есть) или по имени; фото берётся
  из TMDB (путь `/t/p/...` очищается до чистого пути).
- **Компании** — только с ролью `production`.

## Как это работает вместе (для презентации)

```
Запрос из TMDB (TmdbService)
   │ кэш + таймауты + русские ошибки
   ▼
Нормализованный массив (title / page / details / season)
   │
   ▼
MediaLibrary::apply / credits
   │ создаёт/обновляет Media, Person, Company, Genre
   ▼
Запись в БД (moderation_status: external / pending / approved)
   │
   ▼
MediaLibrary::serialize → JSON для клиента
```

**Результат:** TMDB — источник метаданных, а `MediaLibrary` — «переводчик»
между внешним API и внутренними моделями Laravel. Модератор может вручную
поправить одобренное медиа, и TMDB его не перетрет.
