# MovieTracker Frontend

Современный, быстрый и отзывчивый клиентский интерфейс для веб-приложения MovieTracker. Построен с фокусом на отличный пользовательский опыт (UX), производительность и строгую типизацию.

## Структура проекта

Проект использует архитектуру **Next.js App Router** с чётким разделением ответственности:

```text
frontend/
├── app/                      # Next.js App Router (маршрутизация и серверные компоненты)
│   ├── (auth)/               # Группа маршрутов аутентификации (login, register)
│   ├── catalog/              # Страница каталога с фильтрами и пагинацией
│   ├── media/
│   │   └── [id]/             # Динамическая страница детального просмотра фильма
│   ├── layout.tsx            # Корневой layout (шрифты, глобальные стили, провайдеры)
│   └── page.tsx              # Главная страница
├── components/               # Переиспользуемые React-компоненты
│   ├── ui/                   # Базовые компоненты (кнопки, инпуты, модалки)
│   ├── layout/               # Компоненты макета (Header, Footer, Sidebar)
│   └── features/             # Компоненты, связанные с конкретной бизнес-логикой
│                             # (например, EntryForm, CreditsList, AddToListModal)
├── lib/                      # Утилиты и конфигурации (не привязанные к UI)
│   ├── api/                  # Клиенты для запросов к бэкенду (media.ts, entries.ts, auth.ts)
│   ├── utils/                # Вспомогательные функции (например, media-url.ts, cn для классов)
│   └── query/                # Конфигурация React Query (queryClient)
├── public/                   # Статические активы (иконки, заглушки изображений)
├── styles/                   # Глобальные CSS-переменные и кастомные стили Tailwind
├── .env.example              # Шаблон переменных окружения
├── next.config.js            # Конфигурация Next.js (оптимизация изображений, API-домены)
└── package.json              # Зависимости и скрипты
```

## Локальная разработка

### Требования

- Node.js версии **20.x** или выше
- `npm`, `yarn`, `pnpm` или `bun`
- Запущенный Backend API (по умолчанию на `http://localhost:8080`)

### Установка и запуск

1. Установите зависимости:

   ```bash
   npm install
   # или yarn install / pnpm install
   ```

2. Создайте файл окружения на основе шаблона:

   ```bash
   cp .env.example .env
   ```

3. Убедитесь, что в `.env` указан правильный адрес бэкенда:

   ```env
   NEXT_PUBLIC_API_URL=http://localhost:8080/api
   ```

4. Запустите сервер разработки:

   ```bash
   npm run dev
   ```

5. Откройте [http://localhost:3000](http://localhost:3000) в вашем браузере.

## Ключевые архитектурные решения

### 1. Управление состоянием и данными (Data Fetching)

Для взаимодействия с API используется **TanStack React Query**. Это обеспечивает:

- Автоматическое кэширование справочников (жанры, статусы) на 24 часа
- Дедупликацию одновременных запросов
- Плавные фоновые обновления данных (background refetching) без блокировки UI

### 2. Оптимизация изображений

Использован встроенный компонент `<Image />` из Next.js в связке с кастомной утилитой `resolveMediaUrl`. Это гарантирует:

- Автоматическую конвертацию в современные форматы (WebP/AVIF)
- Ленивую загрузку (lazy loading) для изображений ниже первого экрана
- Предотвращение сдвигов макета (**Zero CLS** — Cumulative Layout Shift)
- Корректную обработку как абсолютных, так и относительных ссылок на постеры TMDB

### 3. Анимации и доступность (a11y)

Библиотека **Framer Motion** используется для плавных переходов между состояниями. При этом внедрён хук `useReducedMotion`, который уважает системные настройки пользователя и отключает анимации для тех, кто страдает от вестибулярных нарушений.

### 4. Стилизация

Используется **Tailwind CSS 4** в сочетании с CSS-переменными (`var(--bg-primary)`, `var(--text-muted)`). Это позволяет легко реализовать поддержку тёмной/светлой темы и централизованно управлять дизайн-системой, сохраняя при этом utility-first подход.

## Сборка и Деплой

### Локальная сборка (Production)

Для проверки оптимизированной продакшн-сборки локально:

```bash
npm run build
npm run start
```

Приложение будет доступно на [http://localhost:3000](http://localhost:3000).

### Деплой через Docker

Фронтенд полностью готов к запуску в контейнере. В корне проекта используйте:

```bash
docker-compose up -d --build frontend
```

Образ использует **многоэтапную сборку** (multi-stage build), включая только необходимые файлы `.next/standalone` для минимального размера итогового образа.

### Деплой на Vercel

Проект оптимизирован для развертывания на платформе **Vercel**. Достаточно:

1. Подключить репозиторий GitHub в панели Vercel
2. Указать переменную окружения `NEXT_PUBLIC_API_URL` в настройках проекта
3. Нажать **Deploy**
